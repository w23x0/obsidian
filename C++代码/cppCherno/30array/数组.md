1. 数组的本质与内存布局
数组是相同类型变量的集合
数组在内存中是连续存储的
C++ 数组索引从 0 开始
索引是相对于起始地址的内存偏移

2. 指针算术与实现原理
指针关系：在 C++ 大多数表达式中，数组名会自动隐式转换为一个指向其首元素的指针（即 &arr[0]）
数组下标操作 arr[i] 在底层完全等同于 *(arr + i)。编译器会根据数据类型计算偏移
**核心区别：**
数组名是一个常量，你不能改变它的指向（类似引用）
对数组名使用 sizeof 会得到整个数组的总字节数，
对指针变量使用 sizeof 仅得到指针本身的大小

3. 栈分配 vs 堆分配
栈数组：
在栈上创建，生命周期由作用域决定，离开大括号时自动销毁
内存布局通常是内联（Inline）的，访问速度快，减少内存间接寻址

堆数组
在堆上创建，生命周期由开发者控制，必须使用 delete[] 手动释放
涉及内存间接寻址（Indirection），可能导致性能损耗和内存碎片 

由于数组内部的连续性，无论是栈数组还是堆数组
遍历时都具有极高的 CPU 缓存友好性（Cache Locality），
因为预取器可以很容易地预测并加载接下来的内存数据。

4. 数组大小与边界安全
越界访问：C++ 不会自动检查数组边界，访问越界索引会导致内存访问违规（Memory Access Violation）
越界修改：意外修改其他变量的内存

5. C++ 11 （std :: array）
C++11 引入的标准库容器，相比原始数组（Raw Arrays），
它内置了边界检查和大小跟踪功能，且没有额外的内存开销 

指针加法原理
当你对一个指针进行加法操作时，编译器会根据指针所指向的数据类型自动计算偏移量。
后地址=前地址 + (元素大小 * sizeof(Type))
编译阶段的静态绑定，这种“步长”是在编译阶段确定的。
编译器查阅符号表（Symbol Table）获取 ptr 的类型定义，
并根据目标架构的 ABI（应用程序二进制接口）硬编码偏移倍数。

强制类型转换 改变对某一内存区域或数值的解释方式或存储格式。
在 C++ 内部，指针的类型标签（如 int 或 char）决定了两个物理参数：
寻址步长 (Stride)：执行 ptr + 1 时，内存物理地址增加的字节数。
存取宽度 (Width)：执行 *ptr（解引用）时，CPU 从该地址起始连续读取或写入的字节数。
其步长和宽度的计算方式由编译器在编译阶段根据指针类型确定，并在生成的机器码中硬编码。
分别是  数据类型            
1字节  char bool 
2字节  short wchar_t
4字节  int float
8字节 long long  double    指针本身
在64位系统中，指针通常占用 8 字节（64 位地址空间）。
所以无论指针类型如何，指针占用内存空间都固定的，即与对象大小无关
其步长和读取宽度由编译器根据指针类型定义的规则计算得出，即对象大小
在绝大多数情况下，步长和宽度是一致的。
转成 (char*) 再加 8，这样可以实现以字节为单位的精确控制



强制类型转换运算符（Cast Operator）
在 C++ 中，它的符号形式是 (类型) 或特定的关键字如 reinterpret_cast<类型>。

**特定的关键字**
1. static_cast（静态转换）
相关类型之间的转换,改变数据的存储格式
// 基本类型转换：改变比特位表示
int a = 10;
double b = static_cast<double>(a); 
// 底层：生成 CVTSI2SD 指令，将 32 位整数转换为 64 位浮点数

// 类层次转换：地址偏移计算
struct Base { int x; };
struct Derived : Base { int y; };
Derived* d = new Derived();
Base* b_ptr = static_cast<Base*>(d); 
// 底层：如果是非多重继承，b_ptr 的地址数值与 d 相同。
// 如果是多重继承，b_ptr 会加上相对于 Derived 起始地址的偏移量。

2. reinterpret_cast（重新解释转换）
不改变内存中的任何比特位，仅改变编译器对该地址的“类型标签”
uint32_t val = 0x41424344; // 在内存中（小端序）：44 43 42 41
char* p = reinterpret_cast<char*>(&val);

// 步长改变：
// p + 1 的地址仅增加 1 字节。
// *p 的值是 0x44 (字符 'D')。

3. const_cast（常量转换）
仅在编译器的符号表中移除或添加 const 属性
它仅作用于编译器的符号表，撤销对该指针的“只读”权限检查。
void legacy_api(int* data) { *data = 100; }

const int val = 10;
// legacy_api(&val); // 编译错误：无法将 const int* 转换为 int*
legacy_api(const_cast<int*>(&val)); 
// 底层：编译器跳过类型检查。注意：如果 val 存储在只读内存段（.rodata），
// 运行时的写操作会导致段错误（Segmentation Fault）。


4. dynamic_cast（动态转换）
涉及 RTTI（运行时类型信息） 和 vtable（虚函数表）
struct Base { virtual void f() {} }; // 必须有虚函数以生成 vtable
struct Derived : Base { void f() override {} };

Base* b = new Derived();
Derived* d = dynamic_cast<Derived*>(b);
// 实现原理：
// 1. 访问 b 指向内存的前 8 字节（vptr）。
// 2. 通过 vptr 找到 vtable。
// 3. 在 vtable 附近的 RTTI 槽位查找类型 ID。
// 4. 判断该 ID 是否为 Derived 或其派生类。
// 5. 若匹配，返回调整后的地址；若不匹配，返回 0x0 (nullptr)。
